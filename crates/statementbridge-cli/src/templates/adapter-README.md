# Adapter: __ADAPTER_ID__

This folder was generated by `statementbridge init-adapter __ADAPTER_ID__`.

## How to finish this adapter

1. **Describe the export.** Update `display_name` and `description` so a
   stranger knows exactly which bank/menu/format this handles.
2. **Set detection.** `expected_headers` are the canonical fields whose
   headers must be present for auto-detection (matched through the alias
   table). Add bank-specific header names under `header_aliases`.
3. **Pin formats.** Fill `date_formats` (chrono patterns, e.g. `%d/%m/%Y`),
   `decimal_separator` and `thousands_separator` if the export is consistent.
   Leave them null/empty to let the engine infer.
4. **Choose the amount mode.**
   - `signed`: one amount column with +/− values.
   - `debit_credit`: separate debit and credit columns.
5. **Validate.**

   ```sh
   statementbridge adapters validate adapters/__ADAPTER_ID__/adapter.json
   ```

6. **Test with a synthetic fixture.** Create a small CSV/XLSX that imitates
   the bank's layout with fake data, then run:

   ```sh
   statementbridge convert your-fixture.csv --adapter adapters/__ADAPTER_ID__/adapter.json
   ```

## Rules for contributions

- **Never** include real statements, account numbers, customer names or bank
  logos. Fixtures must be fully synthetic.
- Keep `id` lowercase (`[a-z0-9-]`), stable, and specific
  (e.g. `acmebank-checking-csv`, not `bank1`).
- See `docs/adapter-authoring.md` in the repository for the full guide.
